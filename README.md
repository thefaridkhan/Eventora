# EventSystem deployment

This repository deploys the React client and Express API together as one Render Web Service. The build creates `client/dist`, and the Express server serves it alongside the `/api` endpoints.

## Deploy on Render

1. Push this folder to a GitHub repository. Do not commit `.env` or `node_modules`.
2. In Render, choose **New** → **Blueprint** and select that repository. Render reads `render.yaml` and creates the `event-system` Web Service.
3. Before the first deploy, set these environment variables in the Render service:
   - `MONGODB_URI` — production MongoDB / MongoDB Atlas connection string.
   - `EMAIL_USER` — Gmail address used for OTP and booking emails.
   - `EMAIL_PASS` — that Gmail account's App Password (not its normal password).
4. Deploy. Open the service URL after the deploy succeeds. The health endpoint is available at `/api/health`.

`JWT_SECRET` is generated by Render automatically. The client uses same-origin `/api`, so no `VITE_API_URL` value or CORS configuration is required for this single-service deployment.

## MongoDB Atlas note

If you use MongoDB Atlas, allow Render to reach the cluster (for a quick setup, add `0.0.0.0/0` to the Atlas IP access list and use a strong database user password). Restrict the network rule later if you have a stable outbound IP option.
